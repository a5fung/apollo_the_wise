## 0. In plain words

- **The question:** four reads of 2017-21 (`cb_breakout_definition_2026-10-22.md`, `cb_big_winner_recall_2026-10-22.md`,
  `cb_entry_stop_retry_2026-10-22.md`, `cb_trail_variants_2026-10-23.md`) ran on a file missing about 1 in 4 of the big runners (delisted
  names). Do their conclusions hold on the rebuilt file `cb702_pre_v2`, which puts the delisted names back, removes duplicate companies and
  types every security?
- **Why it cannot just be re-run:** three of our own tables the reads start from do not exist for the rebuilt file, and the two stages that
  make them are once-only reads locked (by file hashes) to the OLD file. Running them on the new file is a new registration — this one.
- **What runs, in order, each once:** the 2017-21 trade read (`pre-read`), the hourly-close entry read (`h60-read --period pre`), the exit read
  (`exit-read --period pre`), the stock-path build (`02_build_paths.py`), then the four reads (`04_relaunch.sh`). Each under a NEW lock that
  pins the rebuilt file's hashes; the old locks are never edited.
- **Minute data: no gap.** Every (date, ticker) pair any stage needs is logged as fetched — 149,093 of 149,093 — and the walks after the entry
  day use daily bars only. Nothing to fetch.
- **The rule for "holds / changes" is fixed in §7 now**, per number, before any new number exists.
- **Nine pieces of build work must land first** (§4, B1-B9) — mainly because the old stages would OVERWRITE the printouts the four docs cite,
  and because a broken pipeline that silently dropped the restored names would otherwise read "holds" on every line (B8). That build, and
  the run itself, wait on the main loop's go (§11).

## 1. The four questions of the standard

1. **Decision served:** whether the four reads' plain-word conclusions about 2017-21 (our trigger fires early; a real breakout adds nothing
   over ordinary stocks on daily bars; we saw about half of the big winners and kept almost none; the 1-ADR stop with two retries holds the
   most doublers; the 20-day reclaim-forgiven trail with no partial holds the most) may lose the *"survivors only"* label
   (`docs/methodology/backtest_data_standard.md` §2), or must be rewritten. No strategy decision rests on it (THE LINE).
2. **What would change it:** any deciding line in §7 whose class moves (an interval that spanned zero now clears it, or the reverse), or a
   share that moves past its tolerance.
3. **What is NOT being asked:** whether breakouts pay (these reads never claimed an edge); anything about 2022-24 (that file already includes
   delisted names) or 2025-26 (sealed).
4. **The control each read uses** stays the one it registered (matched ordinary stocks on the same day, volatility decile and prior 3-month
   strength; seed 702, 2,000 month-block resamples). The control pool now ALSO contains the restored names — the same data on both sides,
   with one exception: the control pools (`02_build_paths.py`, read 1 and read 3's builds) filter on price, dollar volume, history and the
   ticker pattern but NOT on security type, while the entry side does. So the names newly typed as non-stocks (403 old symbols got a type in
   the rebuild, `export_stats.tsv`; UWT, DWT, RUSL, GASL and NBLX among them) leave the entry side only and can still be drawn as controls.

## 7. The numbers compared, old vs new, and the rule — fixed now

**The rules (each line in the tables below names one):**
- **R1 — an interval number** (a difference against the control, or a mean, with its 95% month-block interval). Class = ABOVE (lower end > 0),
  SPANS (lower ≤ 0 ≤ upper), BELOW (upper end < 0). **Holds** = same class on v2. **Changes** = a different class. Beside: "moved" = same class
  but the v2 point estimate outside the old interval.
- **R2 — a registered verdict word** (PASS / FAIL / CAN'T TELL; win / loss / can't tell). **Holds** = the same word.
- **R3 — a share of a population.** Tolerance = the larger of 2 points and the smaller of 5 points and half the old share (44% → ±5; 8.2% →
  ±4.1; 5.2% → ±2.6; 0.6% → ±2). **Holds** = within it. What the band is: the v2 sets CONTAIN most of the old ones, so the old-versus-v2
  difference is far less noisy than two independent samples (one of about 480 at 45% alone has a standard error of about 2.3 points) —
  the overlap makes ±5 a LOOSE band, not a strict one. **What it can detect:** a share moves by (restored fraction) × (restored-minus-
  survivor gap). With restored first breaks at 16.1% of v2 (7,284 of 45,142), moving a share 5 points needs the restored names to differ
  from the survivors by about 31 points; ±4.1 needs about 25, ±2.6 about 16, ±2 about 12. A smaller real difference reads "holds" — so
  every deciding line also prints its restored-only value beside (B8), and `v2_compare.py` prints each line's own restored fraction and
  the gap that line could detect. Where the band came from: set on 10-25 with the 10-23 v2 composition already in view (the big-winner mix
  moved 0.5 to 1.6 points that day) — a composition fact, not an outcome, but not blind either.
- **R4 — a "best cell" claim.** **Holds** = the old best cell is the v2 best, or within 2 points of it on the same share (named as a tie).
- **R5 — a median distance or duration.** **Holds** = same direction and within 25% of the old value; same direction but further = "moved",
  which COUNTS AS HOLDS for the read's conclusion and is named (as R1's "moved"); the direction flips = **changes**.
- **R6 — a raw count.** Never a holds test (counts grow with the restored names, about +19%); reported old / new / ratio.
- **A read's conclusion holds when every DECIDING line holds (a "moved" counts as holds and is named); otherwise it changes, and the lines
  that changed are named.** Beside lines are reported and decide nothing; so are the restored-only values (B8). If a stage's own check fails (§3), its numbers are not compared at all — the failure is the result.
