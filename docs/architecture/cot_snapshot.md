# COT snapshot (`apollo_cot_snapshot.json`)

Read-only nightly export for portfolio-app2's **COT** page: this week's COT index per market, the 12 weeks before it, the last 60 alerts and each market's news watch. Display only — no trade, grade, alert or sizing reads it. Family definition: `docs/setups/cot_family.md`.

| | |
|---|---|
| SQL | `scripts/export_cot_snapshot.sql` (one SELECT over `mi_cot_index_weekly`, `mi_cot_alerts`, `mi_cot_weeks`, `mi_cot_news_watch`) |
| Run | `scripts/auto_export_snapshots.sh`, guarded like the breadth / RS Leaders exports (ON_ERROR_STOP, 300 s timeout, 200-byte floor; a failure keeps the last published file and never blocks the others) |
| Test | `tests/test_cot_export_sql.py` (static SQL checks, the VALUES list vs `cot_family.MARKETS`, the peer list vs `cot_family.PEERS`, the shell guard). no Postgres in the unit suite. Run once by hand against a local PostgreSQL 16.2 (pip `pgserver`) on 2026-11-27, holding the DDL and the 14 alerts of the 11-26 snapshot (one detail double-encoded): the export succeeded and its words matched `cot_family` for all 1,920 (event, market, sign) cases. Check the file after the first 18:30 ET export |

## Rules
- Weeks = distinct `report_date` in `mi_cot_index_weekly`, newest = rank 1 (a holiday-shifted week is still one week). `report_date` = the newest week; `known_from` = the day Apollo first held it (`mi_cot_weeks`).
- Per market: the newest week's `comm` / `lspec` / `sspec` (0-100 index, 0 most short, 100 most long), `setup` / `close_setup` (`short`/`long` = the direction to fade into, else null), `prev` = the week before (null if none), `history` = the 12 weeks before the newest, oldest first. A market with no row in the newest week is not exported.
- `name` and `sector` come from the VALUES list in the SQL (not stored in the DB); a test keeps it equal to `cot_family.MARKETS`.
- Alerts: the newest 60 `mi_cot_alerts` rows, newest first. Labels only; nothing places an order.
- Alert readings (added 2026-11-25, for the page's expandable tile; all additive, the old keys are unchanged): `z` = the market's own day move, (close - previous close) / its 20-day average range, RAW signed (up = positive; a failure is against the crowd, so short set up = negative, long = positive); `peer_z` = the peers' median move in each peer's own range, signed so POSITIVE = the CROWD's way (crowd = long for a short set up, short for a long one; `cot_family.peer_reading`); `comm` / `lspec` / `sspec` = the 0-100 index at alert; `entry_note` + `entry_price` (the failure day's close; null on a Friday row, which enters at the next open); `stop_rule` = plain text; `failure_day` (set on Friday rows); `atr` and `news`[] ({`event`, `class` WITH / AGAINST / INLINE / AMBIG / UNKNOWN, `z` = the surprise vs forecast, **`fact`** (added 2026-11-25: the plain words for that event and the sign of `z`, e.g. "inflation hotter than forecast"; `""` when none or in line), **`read`** (added 2026-11-25: `bullish` / `bearish` / `in line` / `no clear read` for THIS market, derived from `class` and the set up direction: a short set up WITH = bullish, AGAINST = bearish, a long set up the reverse; the page should print `fact` and `read`, not `class`), `first_minute` {`status`, `move` in day-ranges, + = the crowd's way, `big`}}) come from `detail`, which some rows store double-encoded (a JSON string holding the JSON): the SQL unwraps both, and a string that is not an object reads as no detail.
- `peers`[] ({`market`, `name`, `inverse`}) = the markets the correlation reading was taken over, for the alert's market. Derived in SQL from a `peerdef` VALUES list a test keeps equal to `cot_family.PEERS` (chosen over a static map in the page: the page repo then carries no second copy to drift, and the names ride in the file itself). `inverse` = the peer moves the opposite way (Dollar Index vs currencies), already flipped in `peer_z`.
- Old snapshots lack all of these; the page renders them as a plain tile.
- News in plain words (added 2026-11-27, additive, `version` stays 1). Each alert `news`[] item also carries `country` (whose release: US, Australia, Euro area, OPEC+ ...), `release` (which one, with its period when the source gave one: "US GDP (Q3, second estimate)", "US PCE inflation (October)"), `series`[] (the released figures: `name`, `label` e.g. "GDP q/q", `period`, `actual`, `forecast`, `previous` as printed, `vs` = which way it came out in the event's own words: stronger / weaker / hotter / cooler / higher / lower / more in storage / less in storage / a beat / a miss / above forecast / below forecast / as forecast), `surprise`, `why` (one chain ending in the same bullish / bearish word as `read`, e.g. "stronger US growth lifts US interest rates and the US dollar against the New Zealand Dollar → bearish New Zealand Dollar"; empty when there is no read) and `text` (the whole line, as Telegram prints it). Alerts stored before 2026-11-27 get `country`, `release` and `why` FILLED BY THE EXPORT from `newsdef` / `whygrp` / `whydef` (VALUES lists a test keeps equal to `cot_family.RELEASE_NAMES` / `WHY_FAMILY` / `WHY_CAUSE` / `WHY_GROUP` / `WHY`), and `series` only when that day's `mi_cot_news_watch` row for the same market and event holds released figures (`forecast` = its `forecast_after`, the release-day figure the alert was scored on). A stored key always wins. The job never stored the figures of the alerts before then, so they get none (never a fabricated number). Each `news_watch` entry gains `country`, `release` and `why` the same way; its `series` items written from 2026-11-27 carry `label` and `period`. The export SQL was run once against a local Postgres 16 (pgserver) on the 14 alerts of the 11-26 snapshot, and its words compared with `cot_family` for every (event, market) pair, both surprise signs: 0 differences.
- News watch (added 2026-11-25, additive, `version` stays 1, no old key changes; design `docs/design/cot_news_watch_2026-11-25.md`, rules `docs/setups/cot_family.md` §News watch). Each market gains `news_watch`: `[]`, or one entry per scheduled event dated from 7 days back to 7 days ahead (ET today, `(now() AT TIME ZONE 'America/New_York')::date`), ordered by `event_date`, release time, event. Entry: `event` (the type: CPI, NFP, EIA_PETRO, OPEC ...), `event_date` (the session the release belongs to), `release_et` (`YYYY-MM-DD HH24:MI ET`, null for an OPEC+ meeting), `direction` (`short` / `long` = the side to fade into; the crowd is the other side), `level` (main / close), `read` (`mapped` = a crowd read exists for this market, `ambiguous` = a forecast is shown but no crowd read, `none` = no forecast and no read), `crowd_outcome` (the plain "news to watch for" sentence, written by the job; empty unless `mapped`; since 2026-11-25 it states the news and the move in price terms, e.g. "Jobs stronger than forecast (payrolls above 82.0K, unemployment below 4.2%) = bearish Silver. A failure: that news, a first move down, then a close UP."; the column keeps its name), `series`[] (`name`, `forecast` = the last figure read BEFORE the release, `previous`, `actual`, `forecast_after` = the figure the source listed in the judging read), `forecast_seen_at` (when `forecast` was last refreshed, ET text; null = none was seen before the release), `news_class` (WITH / AGAINST / INLINE / AMBIG / UNKNOWN, judged rows only), `surprise_z`, `first_minute` ({`status`, `move`, `big`}, + = the crowd's way), `close_z` (the day's close move in day-ranges, raw sign), `close_against`, `verdict`, `strict`, `alerted`. `series` empty = the source lists no forecast for the event; entries with a null `forecast` = none listed yet. `verdict` (null before the day is judged): `failure_full`, `failure`, `followed_news`, `against_unread`, `shrugged`, `no_failure`, `pending`. `strict` = the three-step rule (news favoured the crowd, first minute their way, close against); `alerted` = a news alert row exists for that market and day (the live, looser rule). Top level gains `news_watch_asof` (newest write to the table, ET text, null when empty) and `definitions.news_watch`. The cards of a market with no entry render as before; the page prints "news watch last updated ..." when `news_watch_asof` is more than one weekday old.
- The page derives "near set ups" (`close_setup` set, `setup` null) and the exit watch (in a set up in `prev`, not now) from these fields.

## JSON contract
`version`, `generated_at`, `report_date`, `known_from`, `markets`[], `alerts`[], `news_watch_asof`, `definitions`.
Market: `market`, `name`, `sector`, `comm`, `lspec`, `sspec`, `setup`, `close_setup`, `prev` {`report_date`, `comm`, `lspec`, `sspec`, `setup`, `close_setup`}, `history`[] (same fields as `prev`), `news_watch`[].
Alert: `alert_date`, `market`, `direction`, `kind` (news / correlation / friday), `level`, `report_date`, `events`, `entry_price`, `stop_price`, `first_minute`, `first_minute_big`, `news_class`, `z`, `peer_z`, `comm`, `lspec`, `sspec`, `entry_note`, `stop_rule`, `failure_day`, `atr`, `news`, `peers`.
News item: `event`, `class`, `z`, `first_minute`, `fact`, `read`, `country`, `release`, `series`[] {`name`, `label`, `period`, `actual`, `forecast`, `previous`, `vs`}, `surprise`, `why`, `text` (any may be missing on an old row).

## Go-live
Server `git pull` (the cron reads the SQL from the checkout); the next nightly export publishes the file. Page: portfolio-app2 `pages/COT.py`.
