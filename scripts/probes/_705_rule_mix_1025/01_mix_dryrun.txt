## The readings this module fixes where the registration is silent (the stricter each time; the module docstring R1-R16)
  R1  Bucket precedence (one function for the real window and every control placement): abstain -> NEITHER; a buy-day firing that is UNRESOLVED -> UNRESOLVED (ahead of EXPLAINS: a firing that may precede his buy explains nothing); a missing minute session between the armed point and the firing -> UNRESOLVED; booked session in the window -> EXPLAINS; before it -> MISS-EARLY; none by the window's end -> UNRESOLVED when a missing session lies at or before the window's end, else NEITHER. The missing sessions are the minute-less sessions for the rules that read 60-minute bars (M-1, M-2s through its arming, the STOP H cells); the touch and daily rules read the daily bar, which a minute-less session cannot hide; a daily hole bounds the path (J_tail) and never precedes a firing.
  R2  The frozen close-fill touch (T, a dated close-proxy fill, a buy-day low at the level — `held_through_intra` marks it unresolved and scans on): two alternatives, the touch after his fill (a buy-day firing) or before it (the later first touch); the bucket is theirs when both agree, else UNRESOLVED (reproduces the mapping table's MISS-EARLY row and never lets the unresolved touch read EXPLAINS).
  R3  An exit_lo `unresolved` of the frozen function (no frame minute on exit_lo) is NOT a buy-day unresolved: the window unit reads it EXPLAINS (§4a), counted in the contradicted line only when a frame contradicts it.
  R4  STOP H cells: the bucket compares the BOOKED session (§4a's table: a close below on the day's last 60-minute bar books on the next session); gate (viii) compares the frozen fields (the event session) row for row.
